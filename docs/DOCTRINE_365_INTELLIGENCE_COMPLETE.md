# Doctrine 365 — Exigence transversale d’intelligence complète des agents COGIA

## Statut
Exigence structurante complémentaire à la Doctrine 365, applicable à l’ensemble des agents COGIA, quels que soient leur nom, leur métier, leur interface ou leurs fournisseurs technologiques.

## 1. Principe fondateur

Chaque agent COGIA est d’abord un agent COGIA. Sa spécialité définit son terrain d’intervention ; la Doctrine 365 définit son niveau d’exigence.

Formulation de référence :

> « Chaque agent COGIA porte une intelligence professionnelle complète, contextualisée, empathique, proactive et gouvernée. Il observe, comprend, s’intéresse, raisonne, prépare, agit dans ses autorisations, contrôle les résultats et conserve les preuves nécessaires. »

Cette formulation n’est pas une déclaration marketing. Elle doit être traduite en comportements observables, capacités explicites, critères mesurables, tests et preuves.

## 2. Position dans la Doctrine 365

Le parcours officiel reste :

**Idée → État de l’art obligatoire → Conception → Apparence → Construction → Validation → Livraison → Évolution**

À l’intérieur de ce parcours, la chaîne d’ingénierie reste :

**Métier → Processus → Règles → Données → Contrôles → Architecture → Fonctionnalités → Tests → Preuves**

L’exigence d’intelligence complète est examinée dès l’état de l’art et suivie jusqu’à la livraison et à l’évolution.

## 3. Ambition de valeur supérieure

Les fournisseurs apportent des capacités : modèles de langage, voix, transcription, vision, recherche, calcul, génération ou exécution.

COGIA doit créer une valeur supérieure à chaque composant pris isolément par :
- la compréhension des métiers et des situations réelles ;
- la qualité des référentiels ;
- la connaissance des processus et des responsabilités ;
- la combinaison gouvernée des modèles, outils et données ;
- la continuité du contexte autorisé ;
- la capacité à conduire une mission jusqu’au résultat ;
- la maîtrise des risques, exceptions et droits ;
- la qualité de la relation humaine ;
- la traçabilité, la vérification et la preuve.

La supériorité ne peut être déclarée sans comparaison sur des missions précises, dans des conditions explicites, avec des mesures et des preuves.

## 4. Dimensions obligatoires de l’intelligence complète

Le socle commun couvre au minimum :

1. **Compréhension du contexte**
2. **Intelligence métier**
3. **Intelligence analytique**
4. **Intelligence décisionnelle**
5. **Intelligence opérationnelle**
6. **Intelligence émotionnelle et relationnelle**
7. **Intelligence anticipative**
8. **Intelligence collaborative**
9. **Intelligence réflexive**
10. **Capacité d’amélioration contrôlée**

Ces dimensions doivent fonctionner ensemble. L’empathie ne doit pas dégrader l’exactitude ; une recommandation doit être réalisable ; une action doit être autorisée ; un résultat doit être vérifié.

## 5. Matrice Doctrine 365 — Intelligence complète

| Dimension | Étapes principales | Livrables attendus | Critères de validation |
|---|---|---|---|
| Compréhension du contexte | État de l’art, Conception, Validation | modèles de situations, intentions, contraintes, informations manquantes | distingue fait, hypothèse et manque ; contexte correctement identifié |
| Intelligence métier | État de l’art, Conception, Construction | référentiels métier, processus, responsabilités, exceptions | exactitude métier, couverture des cas, traçabilité des sources |
| Intelligence analytique | Conception, Construction, Validation | règles d’analyse, calculs, comparaisons, détection d’incohérences | exactitude, robustesse, explication des incertitudes |
| Intelligence décisionnelle | Conception, Apparence, Validation | options, critères, risques, coûts, recommandations | recommandations justifiées, absence d’usurpation de pouvoir |
| Intelligence opérationnelle | Construction, Validation, Livraison | plans d’action, connecteurs, procédures d’exécution | mission aboutie, résultat vérifié, reprise sur erreur |
| Intelligence émotionnelle | État de l’art, Apparence, Validation | profils relationnels, scénarios d’échanges, règles de ton | adaptation mesurée, non-condescendance, prudence sur les émotions |
| Intelligence anticipative | État de l’art, Conception, Validation | signaux faibles, échéances, alertes, scénarios prospectifs | pertinence, faible taux de faux positifs, explicabilité |
| Intelligence collaborative | Conception, Construction, Validation | protocoles de handoff, responsabilités, contextes minimaux | droits préservés, contexte minimal, responsabilité identifiable |
| Intelligence réflexive | Conception, Construction, Validation | règles d’incertitude, escalade, auto-contrôle | détection des limites, erreurs reconnues, escalade correcte |
| Amélioration contrôlée | Validation, Livraison, Évolution | boucle d’amélioration, journal de changements, critères de réévaluation | changements versionnés, évalués, réversibles et validés |

## 6. Socle commun, spécialisation métier et autorisations

### 6.1 Socle commun COGIA
Commun à tous les agents :
- compréhension du contexte ;
- raisonnement et analyse ;
- qualité relationnelle ;
- planification et conduite de mission ;
- gestion de l’incertitude ;
- contrôle du résultat ;
- sécurité, confidentialité, traçabilité ;
- collaboration humain-agent et agent-agent ;
- amélioration contrôlée.

### 6.2 Spécialisation métier
Spécifique à chaque domaine :
- vocabulaire ;
- acteurs ;
- responsabilités ;
- processus ;
- règles ;
- référentiels ;
- documents ;
- risques ;
- contrôles ;
- exceptions ;
- outils ;
- situations de référence.

### 6.3 Autorisations
Indépendantes de la capacité intellectuelle :
- ce que l’agent peut observer ;
- ce qu’il peut analyser ;
- ce qu’il peut recommander ;
- ce qu’il peut préparer ;
- ce qu’il peut exécuter seul ;
- ce qu’il peut exécuter après validation ;
- ce qui lui est interdit ;
- ce qui exige une intervention humaine.

La capacité technique ne vaut jamais autorisation.

## 7. État de l’art obligatoire

Pour tout agent, l’état de l’art doit couvrir simultanément :
- les pratiques professionnelles ;
- les cas ordinaires, complexes, urgents et exceptionnels ;
- les utilisateurs, contraintes et difficultés ;
- les solutions existantes et leurs limites ;
- les capacités agentiques, conversationnelles, vocales et multimodales ;
- l’accès aux connaissances et aux outils ;
- les coûts, risques, dépendances et conditions d’exploitation ;
- les incidents et échecs connus.

Grille minimale :
**Qui ? Quoi ? Où ? Quand ? Comment ? Pourquoi ? Combien ?**

Chaque ambition doit être classée :
- faisable actuellement ;
- faisable sous conditions ;
- nécessitant un développement spécifique ;
- encore immature ou trop incertaine.

Les résultats doivent être datés, sourcés, versionnés et transformés en décisions de conception.

## 8. Référentiels

Chaque agent doit disposer de référentiels structurés couvrant, selon son métier :
- vocabulaire ;
- acteurs ;
- processus ;
- règles ;
- données ;
- documents ;
- risques ;
- contrôles ;
- décisions ;
- autorisations ;
- outils ;
- exceptions ;
- cas de référence.

Chaque élément pertinent doit préciser :
- source ;
- périmètre ;
- version ;
- date de validité ;
- responsable ;
- statut de validation.

Une conversation ou un document reçu ne devient jamais automatiquement une règle faisant autorité.

## 9. Conduite des missions

Logique opérationnelle officielle :

**Observer → Comprendre → Proposer → Préparer → Faire valider lorsque requis → Exécuter → Vérifier → Conserver la preuve**

Pour toute action, l’agent doit connaître :
- l’objectif ;
- les prérequis ;
- les données ;
- les outils ;
- l’autorisation ;
- les conséquences possibles ;
- le critère de réussite ;
- la conduite en cas d’échec.

Une commande envoyée à un outil n’est pas une preuve de réussite.

## 10. Empathie professionnelle

L’agent doit pouvoir :
- reconnaître prudemment des indices d’inquiétude, frustration, incompréhension, impatience ou humour ;
- adapter la longueur, le vocabulaire, le ton et le rythme ;
- éviter les réponses culpabilisantes, condescendantes ou manipulatrices ;
- proposer une aide concrète ;
- transmettre à un humain lorsque nécessaire.

Il ne doit pas prétendre connaître avec certitude l’état psychologique d’une personne ni prétendre ressentir des émotions.

## 11. Sécurité, confiance et résilience

Tout agent doit être conçu sous hypothèse de compromission possible d’une identité, d’un document, d’une mémoire, d’un outil, d’un fournisseur ou d’un autre agent.

Exigences minimales :
- moindre privilège ;
- contexte strictement nécessaire ;
- séparation entre connaissances, instructions et autorisations ;
- protection contre les instructions malveillantes dans les données ;
- contrôle des outils et des handoffs ;
- confidentialité et traçabilité ;
- validations humaines pour les actions sensibles ;
- suspension des actions et modes dégradés ;
- continuité des fonctions essentielles sans IA.

Les autorisations doivent être appliquées par des mécanismes indépendants du seul jugement du modèle.

## 12. Organisation de la suite des agents

Ne pas transformer automatiquement chaque capacité en module visible ou agent distinct.

Pour toute coopération multi-agents, préciser :
- qui reçoit la mission ;
- qui contribue ;
- qui décide ;
- qui exécute ;
- qui vérifie.

Un handoff doit transmettre uniquement :
- l’objectif ;
- le contexte nécessaire ;
- les incertitudes ;
- les autorisations ;
- le résultat attendu.

Il ne doit jamais étendre les droits.

## 13. Interaction naturelle et accessibilité

L’utilisateur doit pouvoir :
- exprimer son besoin avec ses propres mots ;
- comprendre les propositions ;
- suivre l’état d’avancement ;
- voir les informations manquantes ;
- identifier l’action proposée ;
- savoir si une validation est attendue ;
- comprendre le résultat.

Les modalités pertinentes peuvent inclure texte, voix, documents, images ou autres interfaces utiles au métier.

Les contraintes locales, linguistiques, d’accessibilité et de connectivité doivent être étudiées dès l’état de l’art.

## 14. Validation et preuves

Chaque capacité doit disposer d’une fiche comprenant :
- besoin métier ;
- résultat attendu ;
- données et référentiels ;
- outils et dépendances ;
- règles et autorisations ;
- risques et contrôles ;
- scénarios de test ;
- critères d’acceptation ;
- preuves ;
- limites ;
- niveau de maturité.

Scénarios minimaux :
- normal ;
- ambigu ;
- incomplet ;
- contradictoire ;
- urgent ;
- dégradé ;
- utilisateur inquiet ;
- outil indisponible ;
- donnée périmée ;
- demande hors autorisation ;
- tentative de manipulation.

Mesures possibles :
- exactitude ;
- réussite de mission ;
- pertinence de recommandation ;
- qualité relationnelle ;
- délai ;
- coût ;
- robustesse ;
- respect des droits.

Une démonstration réussie ne suffit pas à valider toute une capacité.

## 15. Critères de démonstration d’une valeur supérieure

COGIA peut être déclaré supérieur à un composant ou une solution de référence uniquement si, sur des missions représentatives et documentées, il démontre une amélioration mesurable sur un ou plusieurs critères sans dégrader de manière inacceptable les autres.

Critères :
1. meilleure compréhension du contexte ;
2. meilleure couverture métier ;
3. meilleur taux d’aboutissement de mission ;
4. meilleure qualité de recommandation ;
5. moins d’erreurs ou d’oublis ;
6. meilleure adaptation relationnelle ;
7. meilleure traçabilité ;
8. meilleure conformité aux droits et procédures ;
9. meilleure résilience aux situations dégradées ;
10. meilleur rapport valeur / coût / délai.

Toute comparaison doit préciser :
- scénario ;
- données ;
- version des systèmes comparés ;
- métriques ;
- résultats ;
- limites ;
- date de test.

## 16. Intégration dans les projets existants

Ne pas recommencer arbitrairement les travaux validés.

Pour chaque projet existant :
1. inventorier ce qui est déjà conçu, construit, testé et livré ;
2. mapper l’existant sur les dimensions d’intelligence complète ;
3. identifier les écarts ;
4. classer les écarts : critique, important, amélioration ;
5. définir un plan de mise à niveau sans rupture inutile ;
6. ajouter les tests et preuves manquants ;
7. versionner les changements ;
8. revalider uniquement les éléments impactés.

## 17. Intégration dans les nouveaux projets

Dès l’idée :
1. définir le problème et le résultat attendu ;
2. lancer l’état de l’art métier + intelligence ;
3. caractériser les dimensions d’intelligence nécessaires ;
4. définir les référentiels ;
5. distinguer socle, spécialisation et autorisations ;
6. concevoir les interactions et les parcours ;
7. construire ;
8. tester ;
9. prouver ;
10. livrer et organiser l’évolution.

## 18. Questions ouvertes à traiter projet par projet

Doivent rester explicitement ouvertes tant qu’elles ne sont pas validées :
- profondeur réelle de chaque dimension d’intelligence ;
- niveau d’autonomie par capacité ;
- référentiels faisant autorité ;
- droits d’action ;
- fournisseurs retenus ;
- dépendances externes ;
- seuils d’acceptation ;
- métriques de comparaison ;
- modalités d’escalade humaine ;
- règles de mémoire et de conservation ;
- couverture linguistique et multimodale ;
- contraintes locales ;
- niveau de maturité ;
- exigences de réversibilité.

## 19. Principe de conformité

Ne jamais déclarer automatiquement un agent “conforme Doctrine 365 — Intelligence complète”.

La conformité doit être établie progressivement par :
**Exigences → Réalisations → Tests → Preuves → Validation**

## 20. Formulation de synthèse

**Chaque agent COGIA est d’abord un agent COGIA : sa spécialité définit sa mission ; la Doctrine 365 définit l’exigence de son intelligence, de sa construction et de sa validation.**

L’objectif final est qu’un agent COGIA puisse accompagner une personne ou une organisation depuis la compréhension d’une situation jusqu’à un résultat utile, vérifié, maîtrisé et traçable.
